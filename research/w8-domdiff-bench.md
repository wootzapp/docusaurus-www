## 96.7% fewer evidence losses than screenshot recordings

When a required value sits outside the captured viewport, when the page identity lives in the address bar, or when a control's state is hard to read from pixels, a screenshot-based verifier reasons from incomplete evidence. On the same 100 runs and the same frozen rubrics, W8's DOM-diff Optimized record kept the required evidence far more often.

| Analysis | Tasks | Criteria | Screenshot losses | W8 DOM losses |
| :--- | ---: | ---: | ---: | ---: |
| All loss categories | 100 | 642 | 151 (23.52%) | **5 (0.78%)** |
| URL category excluded | 100 | 642 | 34 (5.30%) | **5 (0.78%)** |
| Listed access-blocked tasks excluded | 88 | 575 | 125 (21.74%) | **5 (0.87%)** |
| Both exclusions | 88 | 575 | 32 (5.57%) | **5 (0.87%)** |

Relative reduction: (151 − 5) / 151 = 96.7% across all categories, and (34 − 5) / 34 = 85.3% once URL losses are set aside.

## Why URLs dominate the screenshot side

The screenshot capture omits the browser's address bar. A missing URL counts as a loss only when the rubric requires exact website, page, record, or endpoint identity and the W8 record preserves that URL. Visible branding and URLs in the shared action history do not substitute for evidence inside the representation itself.

Under that rule, URLs account for 117 of the 151 screenshot losses (77.5%) and for none of the 5 W8 losses. The URL-excluded rows above recalculate the saved findings with the same rubric and the same audit; they describe the non-URL losses across the full audited set.

## Same run. Same rubric. Different evidence.

1. **Record once.** The acting model works from W8's DOM text and executable references. Each task yields one trajectory of actions and ordered browser states, with a screenshot recorded at every state.
2. **Preserve both views.** Screenshots and DOM-diff Optimized come from the same execution, aligned by action step.
3. **Freeze the rubric.** Both verifiers receive the same task, action history, final answer, frozen rubric, and scoring controls.
4. **Score both.** A screenshot verifier and a DOM verifier judge the same criteria from their own evidence.
5. **Audit the sources.** A separate model reviews whether each criterion's required information exists in each representation. Internal WootzApp employees verify every finding.
6. **Count asymmetric omissions.** A criterion counts against a representation only when required evidence is missing there and present in the other.

| Role | Model or reviewer |
| :--- | :--- |
| Browser-action generation | gpt-5.2 |
| Rubric generation and evidence judging, both verifiers | gpt-5.2 |
| Action and validity judging, both verifiers | o4-mini |
| Evidence audit and adjudication | gpt-5.6-sol |
| Verification of audit findings | Internal WootzApp employees |

:::note[Scope of the metric]

The metric covers asymmetric evidence loss. Evidence missing from both representations, agent success, answer correctness, downstream learning gains, and performance on visual tasks are separate measurements.

The confidence intervals are exploratory: they assume independent criteria and do not adjust for correlation within a task or for audit error. The report also lists 12 tasks with website access blockers and 12 recorded execution failures. Those two sets overlap each other and are separate from evidence loss. The full-dataset denominator stays at 642 criteria.

:::

## A better reward starts with a better record

A model judge cannot recover an exact value that was never saved. A deterministic checker also needs the relevant state to have been captured in the first place.

W8's record establishes a measurable reduction in missing browser source evidence, and the audit shows where DOM text falls short: rendered notation, control states, and label–value links. The next engineering step is to turn the preserved evidence into **task-specific checks** for observable state and outcome changes, while retaining screenshot and human or model judgment where visual criteria demand it.
